# grid_layout
GridLayout が非一様列を選ぶ理由、列方向の grow による余剰配分、ragged final row の扱い、ファクトリを設けない判断。

## Swing と違って非一様列にした理由
Swing の `GridLayout` は全セルを同じ幅・同じ高さにする。ラベルと入力欄を並べるフォームでは、これだとラベル列まで入力欄と同じ幅に広がって間延びする。
nimbus の `GridLayout` は列ごとに幅を変える非一様列にした。列幅はその列に入る子の自然幅の最大値で決まる。
これにより「ラベル列は文字ぶんだけ、入力欄列は余った幅ぶん」という、フォームで最も欲しい配置が素直に出る。
等セルが要る用途は稀なので初版では持たず、必要になったら切り替えモードとして足す (`grid_layout.md`「機能要望」)。

## 余剰幅を列方向の grow で配る
コンテナー幅が全列の自然幅合計を上回ったとき、その余りをどこへ配るかを列の `grow` で決める。
列の grow は「その列に入る子の `grow_x` の最大値」とし、余剰を列ごとの grow 比で按分する。
`BoxLayout` が子ごとの grow で主軸方向の余りを配るのと同じ考え方を、グリッドの列に当てはめたものである。
どの列も grow が 0 なら余りは配らず右に残す。入力欄に `setGrowX(1)` を付けた列だけが伸びる、という直感的な挙動になる。

行方向 (高さ) には余剰配分を持たせていない。高さは常に各行の行高の合計で、縦に間延びさせない。行方向の grow は実需が出るまで保留する。

## ragged final row
子の個数が列数の倍数でないと、最終行にセルの欠けが出る。
`GridLayout` は欠けたセルを単に飛ばして配置する。存在する子だけが自分のセル位置に置かれ、欠けた分の幅は詰めずに空ける (列位置は保たれる)。
これにより「3 個の子を 3 列で置いたら 1 行、4 個なら 2 行目に 1 個」という自然な折り返しになる。

## 所有とファクトリ
`GridLayout.create` は確保したインスタンスの `base` (`*LayoutManager`) を返す。
この寿命は差し先の `Container` が肩代わりする (`layout.md`「LayoutManager の所有」)。
`spacing = 0` でも状態 (列数) を持つため、`BoxLayout` のようなシングルトンにはできず常に確保する。

`Application` にファクトリ (`app.gridLayout(...)` 等) は設けていない。
生成は自由関数 `GridLayout.create` だけに寄せ、`BoxLayout` の `horizontal()` / `horizontalSpaced()` と同じ「レイアウトは自由関数で作る」流儀に揃えるためである。
