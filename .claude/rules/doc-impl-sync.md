# doc-impl-sync
doc と実装の追従関係についての不変条件。
md を編集するときだけでなく、コードを変えて doc を直し忘れたときにも効く。
（`vendor/` 配下は対象外。nimbus 自身の 3 レイヤーのソースと doc にのみ適用する。）

## 追従の向き
実装が doc を追い越しているのは場合により※許容（doc にないけど実装にある）。
実装が doc に追いついていないのは NG（doc にあるのに実装にない）。
ただし `機能要望` / `棚上げ中` など、未実装と明示されたセクションはこの限りでない（そこは意図的に先行記述する場所）。

※利用者が適切なタイミングで呼ばないと壊れるようなメソッドなら doc に明記必要、
public ではあるが基本フレームワーク内で完結なら doc への明記不要。

## 改名の取りこぼし
doc と実装で同じ目的のフィールド / メソッドが別名になっているのも NG
（別物の増減ではなく 1 つの改名の取りこぼしとして扱う）。
解消は基本、実装の名前に寄せて doc を更新する。
doc を起点に実装を改名し直すのは audit を潰すには重いので避け、doc 側は後で必要に応じて整える。
