# dogfooding バックログ
ドッグフーディングアプリ（`examples/app_*`）側の機能積み増しを記録する。
運用規約は [backlog.md](backlog.md) に従う。

framework の部品が要るものはここではなく [framework_backlog.md](framework_backlog.md) に置き、
ここからは依存として参照する（例: 詳細表示 → framework#9 Table）。
ここに積むのは「既存部品で書けるアプリ側の作業」が基本。

このリストは網羅ではない（作者: 「さらにその先もあるとさえ思っています」2026-06-12）。
実機を触って出てきた要望を随時追記する。

## #1 拡張子ごとのファイルアイコン
- 状態: 未着手
- 優先度: 低
- 影響範囲: app_filer（FileCell の icon 選択ロジックのみ）
- 更新日: 2026-06-12
- 依存: なし

### 何
現状はフォルダ / ファイルの 2 種だけ。拡張子 → lucide アイコンのマッピングを足す
（.zig/.c/.md → file_code / file_text、画像 → file_image 等）。OS のシェルアイコン取得はスコープ外。

### 完了条件
代表的な拡張子 10 種程度で行アイコンが変わる。

## #2 サイズ / 更新日時の擬似カラム
- 状態: 未着手
- 優先度: 中
- 影響範囲: app_filer（Entry にメタデータ追加、FileCell を固定幅レイアウトに）
- 更新日: 2026-06-12
- 依存: なし（framework#9 Table が来たら本物の詳細表示に置き換えて廃止する前提の暫定）

### 何
行セルを「アイコン+名前 | サイズ | 更新日時」の固定幅 3 区画にする。ヘッダー・ソート・列幅変更は無し
（それらは framework#9）。Entry 構築時に stat 相当を取る必要がある（列挙が遅くなるならその時点で考える）。

### 完了条件
一覧でサイズと更新日時が読める。framework#9 完了時にこの暫定実装を撤去する手順がコメントで残っている。

## #5 再帰検索
- 状態: 棚上げ
- 優先度: 中
- 影響範囲: app_filer（検索ボックス + 結果リスト）、非同期実需の起点
- 更新日: 2026-06-12
- 依存: なし（**io.async + invokeLater の初実戦**として位置づけ。2026-06-12 作者と合意した「非同期は実需が出てから」の実需がこれ）

### 何
名前部分一致のサブツリー検索。ディレクトリ歩きは遅い（実需として正当）ので
`io.async`（または std.Io.Dir.Walker + スレッド）で回し、ヒットを `invokeLater` で UI へ逐次反映、
キャンセル可能にする。痛みが見えたら SwingWorker 相当のヘルパーを framework に切り出すか検討する。

### 完了条件
大きなツリーで検索中も UI が固まらず、結果が逐次出て、再検索 / キャンセルが安全。
非同期パターンの知見（ヘルパー化するか否かの判断材料）がバックログかメモに残る。
