## 2. エラー型 / エラーハンドリングのバラツキ

### エラーセットの分布

`framework/src/*.zig` および `awt/src/*.zig` のいずれにも、**名前付き `error{...}` セットの宣言は 1 件も存在しない**。すべての fallible 関数は inferred error set (`!T`) を使う。

awt 層の `return error.Xxx` リテラル例:
- `awt/src/Device.zig:9` `init() !Device`
- `awt/src/Swapchain.zig:13` `init() !Swapchain`
- `awt/src/Pipeline.zig:73` `init() !Pipeline`
- `awt/src/EventQueue.zig:48` `init() !*EventQueue`
- `awt/src/Image.zig:20` `fromMemory() !Image`

framework 側は `error.Xxx` を新規生成している箇所が 1 つも無く、すべて awt または `std` の error を素通しする形。

→ C ABI 変換層で網羅可能なタグ集合を確定させるためには、少なくとも公開 API 境界（`framework/src/Application.zig`, `framework/src/Window.zig`）の戻り値を名前付きエラーセットへ昇格させるのが望ましい。

### 命名のバラツキ

「初期化失敗」系の `Failed` 接尾辞:
- `awt/src/root.zig:39` `error.AwtInitFailed` — **唯一の非対称（`Init` + `Failed` 二重表現）**
- 他はすべて単一動詞 + `Failed`: `DeviceCreateFailed`, `WindowCreateFailed`, `SwapchainCreateFailed`, `SwapchainResizeFailed`, `BufferCreateFailed`, `TextureCreateFailed`, `RenderTargetCreateFailed`, `CommandBufferAcquireFailed`, `PipelineCreateFailed`, `FontCreateFailed`, `ShaderCompileFailed`, `RootSignatureCreateFailed`

→ `AwtInitFailed` を `AwtInitializeFailed` か `AwtCreateFailed` に揃える価値あり。

「容量超過」系が 3 つに分裂:
- `awt/src/VertexRing.zig:44` `error.VertexRingFull`
- `awt/src/UniformBuffer.zig:62` `error.UniformBufferFull`
- `awt/src/GlyphAtlas.zig:100` `error.GlyphTooLargeForAtlas`
- `awt/src/RootSignature.zig:25` `error.TooManyBindings`

→ `XxxOverflow` 等で統一可能。

その他:
- `awt/src/RenderTarget.zig:41` `error.ReadbackFailed` — サブジェクトが冠されていない（`RenderTargetReadbackFailed` が筋）。
- `awt/src/Font.zig:71` `error.GlyphRasterizeFailed` — `Glyph` 接頭辞は OK だが、後述「容量超過」の `GlyphTooLargeForAtlas` と接頭辞ルールがズレている可能性。

### C ABI 変換の欠落

`framework/src/c_api.zig` は現状 5 行、`nmGetBackendVersion` の素通しだけ。CLAUDE.md「エラーのC_ABIでの表現」節が定めた以下が全て未実装:

- threadlocal の `last_error` 退避
- `setLastError(err: anyerror) void`
- `nimbus_last_error_code()` / `nimbus_last_error_message()`
- `errorToCode(err: anyerror) c_int` の switch — 上述で洗い出した 20 種類のタグを網羅する必要あり
- 公開関数 `nmCreateApplication`, `nmCreateFrame`, `nmCreateButton`, ... — 1 件も export されていない
- `nmDestroyXxx` 対の export — 未着手

推奨順:
1. `framework/src/error.zig` を新設しタグ⇔コードの対応表を一元管理
2. `c_api.zig` に `setLastError` / `last_error_code` / `last_error_message` を先に実装
3. `nmCreateXxx` を 1 個ずつ追加する際に CLAUDE.md「関数の失敗時の保証」（失敗時の自動巻き戻し）を `errdefer` で確認

### errdefer の漏れ

**明確な漏れは 1 件のみ**: `framework/src/Application.zig:166-189` `frame`
- `:167` で `Frame` 確保 → `:168` で `errdefer destroy(f)` を張る
- `:169` の `Frame.init` 成功後、`:182` の `self.windows.append` が OOM で失敗すると **`Frame.deinit()` (Window/Swapchain/title_dup の解放) が呼ばれない**
- 修正: `:169` 直後に `errdefer f.deinit()` を追加

**半漏れ**: `framework/src/Window.zig:274` `addOverlay`
- `:276` の `putProperty catch {}` で副作用（DirtyNotify property 登録）を行うが、`:277` の `overlays.append` が失敗しても property は残置される
- 上述「握りつぶし」と二重で問題

その他全関数（Application.init / Window.init / 各 Container/Panel/Label/Button/Slider/Menu/MenuItem/CheckBoxMenuItem/MenuBar/MenuSeparator/PopupMenu の create、awt の Image/Swapchain/Pipeline/Texture/Buffer/Shader/RenderTarget/RootSignature/Font/Device/VertexRing/UniformBuffer/CommandBuffer/Window/EventQueue/QuadIndexBuffer/GlyphAtlas/programs の init）は **漏れなし**。

### カバレッジ欠落（高リスク）

1. **`BoundedRangeModel.setRange` の extent 縮小** (`framework/src/BoundedRangeModel.zig:44-53`) — `value < min` のとき value を min まで持ち上げるが、その後 `value + extent > max` 判定で更新後 value を使うか元 value を使うかでクランプ結果が変わる。`setExtent` (`:55-60`) も value > max の不整合状態を防いでいない
2. **`Slider.posToValue` のゼロレンジ** (`framework/src/Slider.zig:126-139`) — `total > 0` チェックはあるが `range = max - min` がゼロ／負のときの動作が未定義
3. **`ChangeListenerList.fire` 中の add/remove** (`framework/src/ChangeListenerList.zig:45-53`) — コメントは「fire 中の変更は反映されない」だが、実装は `len` スナップショット + `items.items` 直接参照。`orderedRemove` が呼ばれると別スロットを誤読する可能性
4. **`Container.remove` 中の連鎖 remove** (`framework/src/Container.zig:78-90`) — orderedRemove の while ループで、リスナー経由で別の子が remove されると index がずれてスキップが発生し得る
5. **`BorderLayout.doLayout` 負方向のレイアウト** (`framework/src/BorderLayout.zig:92-112`) — north + south min_size 合計が container 高を超えると west/east/center が height=0 になり Graphics.clip の空 rect パスが必ず通る。そのクランプの正しさを検査するテストが無い
6. **`EventQueue.drain` の reentrance** (`awt/src/EventQueue.zig:142-166`) — 「drain 中の invokeLater は次回 drain」というコメントの不変条件をテスト化していない
7. **`Window.dispatchInput` の overlay/mouse_capture 優先順** (`framework/src/Window.zig:376-460`) — 状態空間が広いがハーネス上はテスト可能（偽 component + Event 注入）
8. **`PopupMenu.show` の画面外配置クランプ** (`framework/src/PopupMenu.zig:96-99`, `framework/src/Menu.zig:201-202`) — popup 自体が win 幅より広い場合に負方向にはみ出す

### ハーネス所見

- GPU 初期化失敗時のスキップは適切（`awt/tests/snapshot_test.zig:73,75` で `SkipZigTest`）
- awt の terminate を意図的にリーク（テストランナーがプロセス終了するため OK、コメント済み）
- fixture ブートストラップは race を考慮していないが、各 test が別 scene を書くため実害なし
- 許容差は ±1 LSB 固定 (`awt/tests/snapshot_test.zig:21`)。`doc/test.md:82-90` の方針通り
- 失敗時アーティファクト書き出しは `catch {}` で握り潰されるが、本来のテスト失敗をマスクしない設計
- **明確に欠けているハーネス**: `doc/test.md:92-118` で予定されている framework のレイアウトテスト基盤 (`framework/tests/layout_test.zig`) が未実装。`framework/tests` ディレクトリ自体が存在しない

### High (TextField 前に潰す)
